## Лабораторная работа №1. Источники задач и контракты

### Задача

Реализовать систему приёма задач из разных источников без использования общего базового класса.

### Структура проекта

 <pre>
    .
    ├── src/                 # Исходный код проекта
    │   ├── protocols/       # Контракты Protocol
    │   ├── receiver/        # Приемник задач
    │   ├── sources/         # Источники задач
    │   ├── task_model/      # Модель Task
    │   ├── exception.py     # Исключения
    │   ├── main.py          # Точка входа
    │   └── tasks.json       # Тестовые данные
    │
    ├── tests/               # Pytest тесты
    ├── requirements.txt     # Зависимости
    ├── pyproject.toml       # Конфигурация проекта
    └── README.md            # Отчет
</pre>

### Реализация

### Task

Реализован через `@dataclass`.  
Содержит `id: int` и `payload: Any`.

### Контракт

Используется `Protocol` и `@runtime_checkable`.  
Источник обязан реализовать `get_tasks() -> list[Task]`.

### Источники

- `GeneratorTaskSource` - задачи, генерируемые программно
- `FileTaskSource` - задачи, загружаемые из файла
- `ApiTaskSource` - задачи, получаемые из API-заглушки

## Лабораторная работа №2

### Модель задачи: дескрипторы и `@property`

### Цель работы

Изучить дескрипторы и `@property`, чтобы контролировать доступ к атрибутам и получать вычисляемые свойства объекта.

### Задание

Реализовать класс `Task`, который хранит id, описание, приоритет, статус и время создания задачи.

### Структура проекта

 <pre>
    .
    ├── src/                 # Исходный код проекта
    │   ├── protocols/       # Контракты Protocol
    │   ├── receiver/        # Приемник задач
    │   ├── sources/         # Источники задач
    │   ├── task_model/      # Модель Task, дискрипторы
    │   ├── exception.py     # Исключения
    │   ├── main.py          # Точка входа
    │   └── tasks.json       # Тестовые данные
    │
    ├── tests/               # Pytest тесты
    ├── requirements.txt     # Зависимости
    ├── pyproject.toml       # Конфигурация проекта
    └── README.md            # Отчет
</pre>

### Что сделано

В `task_model/descriptors.py` созданы дескрипторы для проверки и защиты основных полей задачи.  
В `task_model/task.py` реализован класс `Task`, который использует эти дескрипторы и методы `start()`,
`complete()`, `cancel()` для изменения статуса.

### Свойства

Через `@property` добавлены:

- `is_ready`
- `is_in_progress`
- `is_completed`
- `age_seconds`

Также `status_label` возвращает текстовое название статуса.

Работа проверялась с помощью `pytest` и запуска программы:

запуск тестов

```bash
pytest tests/ -v
```

```bash

```

## Лабораторная работа №3

### Итераторы и потоковая обработка задач

### Цель

Реализовать коллекцию задач с ленивой обработкой, поддержкой повторного
обхода и фильтрации

### Реализация

**ReplayableTasks** - читает задачи по одной через `next()` - кэширует их - позволяет повторно итерироваться

**TaskQueue** - Поддерживает `for`, `list`, `sum` - Ленивые фильтры через `yield` - работает с любыми Iterable - Не загружает все данные сразу

### Фильтрация

``` 
queue.filter_by_status("new")
queue.filter_by_priority(min_priority=1)
```

Реализована через генераторы без создания списков

### Особенности

- Ленивые вычисления `yield`
- Кэширование без полной загрузки
- Повторный обход
- Эффективная работа с памятью

